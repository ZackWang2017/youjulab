# 独立量化研究 Agent：可行性与详细设计

日期：2026-10-30。状态：技术方案，尚未实现、未执行量化框架集成验证。

## 1. 结论与可行性边界

可行目标：用户自然语言提出研究问题；独立 Agent 检查数据、制定实验、选择已接入工具、编写 Python、在隔离环境执行、根据错误有限修复、输出可追溯研究结果。前端无需按策略类型固定表单。

不可承诺目标：任意金融问题都能全自动完成、缺少数据也能准确回测、代码运行成功即可证明策略实现正确，或自动挖掘出可靠盈利策略。

本方案是基于开源项目官方文档与现有仓库代码的架构判断，不能替代模型、数据、沙箱、引擎适配的实际验证。建议先做可丢弃的验证工程，通过验收后再接正式页面。

| 研究任务 | 可行条件 | 缺少条件时的行为 |
| --- | --- | --- |
| 固定权重配置及再平衡 | 可确认的具体标的、完整收益序列、交易或指数测算口径 | 请求补齐映射或缩短区间，不能悄悄换标的 |
| 日频/月频动量、规则选股 | 历史价格、历史股票池、可交易状态及执行假设 | 明确限制或拒绝相应策略 |
| 因子有效性检验 | 因子观察值、未来标签、股票池及时间对齐可验证 | 输出数据诊断，不输出假指标 |
| 基本面历史因子 | 公告可用时点、财务口径、历史修订、估值分母、币种等可追溯 | 无 PIT 数据时不能标记为可信历史回测 |
| 自动训练及模型研究 | 时间切分、资源预算、受保护的样本外数据 | 不进行无界参数搜索 |
| 高频、复杂衍生品、实盘交易 | 另行接入订单级数据、专用模拟及交易设施 | 首期不支持 |

| 项目 | 确认的能力 | 使用决定 |

## 3. 当前工程的实际基础与缺口

可复用：

- `apps/office-copilot-web`：持仓/资讯的导航布局、对话与状态展示、已有 ECharts。
- `apps/office-backend`：用户认证、用户模型配置解析、资产权限和文档引用。
- `mcp-server/financial-data-service`：股票搜索、财报与指标服务，保持 endpoints/service/repository 三层。
- `mcp-server/portfolio-service`：行情与持仓逻辑。

代码核查发现的限制：

- `portfolio-service/repository/market_quote_repository.py::fetch_daily_closes` 当前使用腾讯前复权日 K，单次参数最多 800 条；不能据此承诺完整十年历史或已正确处理全部公司行动。
- `financial-data-service/service/market_service.py` 主要提供当前档案、latest/y1/y2 报表及指标，并非历史时点特征服务。
- `financial-data-service/service/statement_refresh.py` 明确采用同报告期覆盖更新；不能把这套更新后的财报直接视为保留了历史修订版本的 PIT 数据集。
- 以上是本次检查到的接口限制，不等同于断言所有市场数据均不存在。实施前仍需逐数据源盘点覆盖率与使用权限。

## 4. 部署与职责

用户 Web → office-backend 鉴权/BFF → 独立 quant-research-agent API → 持久化任务队列 → Agent worker → 工具适配器/隔离执行器。

独立部署指后端服务隔离，用户仍在原有“策略”页面内使用，无需打开另一套网站或安装本机运行环境。

职责划分：

- Web：研究对话、明确假设、源代码预览、运行进度、图表和历史比较。
- office-backend：身份及权限、用户模型调用代理、现有知识资产的授权引用。
- Agent API：研究项目、对话、任务、事件及结果查询。
- Worker：恢复检查点、决策和工具调用；不在 Web HTTP 请求里同步跑完整研究。
- Data broker：解析证券、数据覆盖检查、快照与口径元数据；外部数据凭据留在此层。
- Sandbox runner：执行限定镜像及代码，只读取授权快照，写入本次任务输出目录。
- Trusted evaluator：使用引擎产物校验与复算，结果是否通过不由报告模型决定。

开发验证阶段可以在一台 Linux 主机部署这些进程；正式多用户 Web 部署再拆分 worker。Mac 仅用作 Web 开发端即可。

## 5. 一个 Agent，多种工具能力

对用户呈现一个量化研究 Agent。内部按需运行规划、编码、检查和报告步骤；不同步骤可复用同一模型，不必一开始建立多个相互对话的 Agent。

工具列表由服务端维护。每项能力声明：

- 工具名称、版本、输入/输出 JSON Schema。
- 能处理的任务和不能表达的交易语义。
- 需要的字段、时间频率、市场、币种及 PIT 条件。
- 可用环境、预计资源级别、超时、可重试错误类型。
- 授权范围、输出证据及结果校验方式。

Agent 可以组合工具、生成自定义 Python 模块，但不能临时安装未知包、下载执行陌生仓库，或凭提示词创造一个没有注册的工具。

工具路由：模型提出选择及理由，确定性能力检查器验证兼容性。工具不支持的语义明确退回，不静默降级。

示例能力：

| 工具 | 输入 | 输出 |
| --- | --- | --- |
| resolve_instruments | 名称、代码、市场、资产类别 | 候选标的及歧义 |
| inspect_data_coverage | 字段、区间、频率、股票池 | 缺失、覆盖、来源及 PIT 状态 |
| create_data_snapshot | 已授权标的/字段/时点要求 | 快照 ID、清单、哈希 |
| inspect_engine_capabilities | 研究需求 | 可用引擎与不支持项 |
| write_research_files | 文件补丁 | 源码版本、变更摘要 |
| run_semantic_checks | 研究合同与源码 | 规则测试和时间对齐诊断 |
| submit_experiment | 代码版本、快照、环境、预算 | task ID，异步状态 |
| inspect_experiment | task ID | 日志、错误及产物引用 |
| validate_results | 引擎产物、实验合同 | 复算指标、检查结果、限制 |
| compare_experiments | 指定 run IDs | 口径兼容性与对比表 |
| build_report | 已验证结果引用 | 说明、图表及证据关联 |

Python/pandas/scipy 可以执行探索性研究；bt/Qlib 是专项工具，不是唯一允许的程序形态。交易组合的资金、持仓和费用优先由成熟引擎计算，不能每次让模型重写账本。

## 6. 研究流程与停止条件

1. 解析目标：保存原始问题和附件，区分研究问题、执行假设与报告要求。
2. 探测数据和工具：先确定能否做，再决定实现；不能在数据还不确定时承诺回测结果。
3. 补齐关键含义：对自由现金流定义、候选指数、执行日期等有重大影响的歧义一次集中提问。
4. 形成研究合同：列明问题、公式/逻辑、数据、评估方法、区间、执行口径、预算和预期输出。它不是限制算法的固定策略 DSL，算法仍由源码表达。
5. 制定实验计划：先基线，再目标方案；仅按需求添加对照或敏感性实验。
6. 生成实现：检索锁定版本 API 和本地可运行示例，写源码及关键语义测试。
7. 小样本试跑：验证依赖、字段、时间对齐、资金流和输出结构。
8. 正式执行：任务持久化，支持取消、超时、失败恢复。
9. 验证结果：通过后生成报告；运行成功但验证失败的产物只能放入诊断区。
10. 结束或继续：回复用户提出的问题；新研究假设建立子实验，保留原结果。

允许自修复接口名、导入、字段类型等程序问题。修改定义、股票池、回看周期、费用、执行时点或数据代理属于研究含义变化，要明确展示并按用户授权继续，不能为了运行成功偷改策略。

建议验证期默认上限：每个实验最多 3 次程序修复，最多 3 个正式实验，累计模型调用最多 20 次，单次沙箱最长 10 分钟。数值是初始产品预算，不是性能承诺；训练任务另设配置。到上限输出已完成内容和失败原因。

状态：draft、planning、needs_input、queued、running、validating、completed、partial、failed、cancelled。

- partial：例如数据诊断成功，但缺少 PIT 数据导致回测未执行。
- completed：预先声明的目标产物和校验满足；不表示策略盈利或经济规律已获证明。
- 关闭浏览器只断开事件订阅，不取消任务；用户明确取消时停止 worker 子任务并终止沙箱。
- 持久化 task ID、工具调用幂等键和沙箱 ID；恢复前查询原任务，避免检查点重放导致重复计算或计费。

## 7. 数据与金融语义

数据快照至少记录：来源、抓取时间、覆盖区间、交易日历、时区、币种、单位、字段定义、复权/全收益口径、分红处理、缺失规则和内容哈希。

基本面数据另需报告期、披露可用时间、历史修订版本及其生效时间；历史股票池另需成分调整和退市信息。

区分四种产品输出：

- 指数全收益配置测算：是资产类别代理测算，不冒充实际可买产品的交易记录。
- ETF/证券交易回测：明确价格、分红、成交约束、费用及可交易性。
- 因子检验：允许使用未来收益作为标签，但标签和信号构建必须分开。
- 基本面探索：若无完整 PIT，只输出明确标注限制的探索结果或数据诊断，不能认定为合格回测。

前复权价格、原始价格、分红现金和全收益序列不能混用而重复计息。数据不足不得无提示前向填充上市前价格、插入零收益或用当前成分股冒充历史成分。

多市场策略需定义市场休市时的持仓估值和下一次可成交时间；共同币种下包含汇率口径。首版选一个市场/币种减少歧义。

## 8. 执行隔离与可信计算

不能在 office-backend 或 MCP 主进程里 exec 用户生成代码。Python 子进程或 AST 黑名单都不等于沙箱。

单任务隔离环境：固定依赖镜像、非 root、只读根文件系统、独立临时写目录、只读授权数据快照、网络默认关闭、限制 CPU/内存/进程数/运行时间/磁盘输出。

正式多用户服务应验证 Docker 配置并采用 gVisor 或独立虚拟机等更强隔离；普通容器不作为绝对安全保证。Docker socket 不可挂入任务，沙箱不能获得宿主 `.env`、LLM key、用户令牌或数据库路径。

Agent 控制进程调用模型代理；不把模型密钥交给生成的研究程序。模型代理按每个任务绑定的用户和 LLM_CONFIG_SET 解析现有配置，避免进程级环境变量切换造成串号。

任务文件和附件作为数据处理，不能提升工具权限。输出图表以经校验的声明式 JSON 或静态图片展示，不直接执行生成的 HTML/JS。

## 9. 结果可信度，而非模型自评分

检查分为四层：

- 程序层：导入、语法、Schema、异常、资源限额。
- 策略语义层：确认生成的规则与用户目标一致，用已知小数据集验证选择、赋权、日期、再平衡和费用。
- 时间因果层：历史时点的数据可见性、训练/验证/测试区间、信号与交易的先后关系；交易信号接口只提供当时可见的数据窗口。
- 会计与结果层：资金/持仓/费用关系、权重边界、日期对齐、净值及收益贡献复算。

未来标签可以提供给因子评估器，不可提供给交易决策代码。静态扫描和截断数据一致性测试能发现一部分泄漏，但无法证明任意 Python 程序绝无未来信息；不应宣称自动验证可以彻底解决这一问题。

可信 runner 保存标准引擎的净值、持仓和交易轨迹；独立评估器复算核心指标。模型提交的 metrics.json 不能直接成为最终事实。

预先固定 holdout 区间和实验预算；调参阶段不向 Agent 反复暴露样本外成绩。保留全部尝试而不是只展示最优结果，阴性结果也正常完成。

报告中的数字引用结果文件/指标键；文字结论区分观测、推断和限制。错误修复成功与研究假设成立是两个概念。

## 10. Web 交互

左侧一级入口：持仓、策略、资讯。策略归属用户，可授权关联知识项目；不改变原用户—项目—资产路径。

顶部：研究方案下拉（列表、重命名、新建、删除）｜研究｜运行记录｜结果对比。

新建只要求名称。可展示示例问题，但不强制选资产配置/因子等类型。

研究页左侧对话，右侧研究说明、程序与参数、研究结果。运行前显示关键假设和数据可用性；普通参数可直接修改，复杂逻辑继续用自然语言或源码编辑。

复用 ThinkingStatus 的容器样式，显示计划、已调用工具、执行摘要、错误与进度，不把展示模型内部长推理作为功能依赖；没有真实百分比时仅显示阶段。

刷新后由 run ID 恢复状态和历史事件，不重新提交任务。用户修改运行中的研究会生成新 revision，当前任务继续使用不可变快照。

结果支持 metric、timeseries、table、image、markdown、file 六类产物。表格和曲线可按需加载，返回给模型的只是统计摘要和证据引用，不把十年行情塞入提示词。

## 11. 持久化与接口草案

对象：research_projects、research_revisions、research_messages、research_runs、research_events、tool_invocations、data_snapshots、research_artifacts。

每条记录带 owner_id；project 关联可选。对话、工具调用、代码、数据快照、环境、结果之间必须可追溯。checkpoint 是运行恢复设施，不替代业务表。

个人开发验证可用独立 SQLite、单 writer 和文件产物；多 worker 的 Web 部署优先使用服务型关系数据库和对象存储，不让多个服务共享挂载同一 SQLite 文件。复用现有基础设施，不能为了 Agent 默认引入一套重复数据库。

建议公开 API：

- POST /research-projects：创建研究。
- POST /research-projects/{id}/messages：提交自然语言及附件引用。
- POST /research-projects/{id}/runs：冻结指定 revision 并创建任务，支持幂等键。
- GET /research-runs/{id}：状态和产物。
- GET /research-runs/{id}/events：SSE，支持 event ID 续传。
- POST /research-runs/{id}/resume：回答歧义问题并恢复。
- POST /research-runs/{id}/cancel：取消。
- POST /research-comparisons：指定运行记录比较，先检查口径兼容性。

网页通过 office-backend BFF 访问服务；独立服务验证服务身份和用户委托，两者分开。用户身份不可由请求体任意传入。每个 checkpoint、任务、产物、附件都做归属检查。

内部 Python 工具通过本地适配器调用引擎，不为 bt/Qlib 每个函数额外搭 MCP。已有数据能力通过现有 MCP/REST 使用；将来给外部 Agent 开放研究入口时，在 mcp-server 下增加独立业务包并保持三层结构。

## 13. 如何验证值得继续，而不是强行实现

第一关：数据可用性。选定市场和标的，能拿到可追溯历史序列与基准；若做基本面，另行检查 PIT。过不了就只完成数据方案，不做漂亮但无依据的收益页。

第二关：最小独立 Agent。先不写正式 Web 页面，在测试客户端完成：自然语言→检查数据→选工具→代码→试跑→执行→验证→结果。

第三关：固定验收集。至少覆盖以下案例，每个可执行案例建议重复 3 次测试稳定性，并人工审阅代码是否表达原意：

| 案例 | 必须验证的行为 |
| --- | --- |
| 四资产固定配置 | 与确定性基线的净值、再平衡和费用一致 |
| 月度动量轮动 | 信号形成与下一可成交时点正确 |
| 自定义规则 | 能使用 Python 实现，未硬套预设策略类别 |
| 单因子研究 | 因子与未来标签分离，IC/分组结果可复算 |
| 基本面因子缺 PIT | 明确停止或返回受限探索，不冒充可信回测 |
| 字段/接口错误 | 在预算内修复，不改变研究规则 |
| 数据缺失/标的歧义 | 询问或停止，不无提示替换 |
| 重启/断网/重复提交 | 恢复而非重复启动任务 |
| 取消/超时/越权 | 执行真正终止，不能读其他用户文件 |

数值验收：在相同输入及执行口径下，对确定性参考案例预先规定容差；例如验证期采用净值序列最大绝对差不超过 1e-8（浮点和引擎实现需要明确），不能在看到结果后放宽容差。策略语义、越权及泄漏反例不能以平均成功率掩盖。

若选择的模型在多次独立试验中不能稳定遵循目标、正确调用工具并通过语义验证，应停止正式集成，输出具体失败样例；考虑退回辅助编码或研究说明工具，不宣称自动研究已完成。

第四关：接入最小 Web 工作区。通过前面验收后，再实现导航、对话、事件、结果和版本；首个引擎为 bt，自定义 Python 分析作为补充。Qlib 与 RD-Agent 按真实研究需求逐步接入。

不预先承诺通用任务成功率、固定模型成本或完成周期。先记录验证集上的完成率、语义正确率、人工干预次数、数据阻塞、模型调用量、耗时及资源，再做正式建设决策。
